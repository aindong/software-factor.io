# `softwarefactor cost --json`

## Goal

`softwarefactor cost --json` prints the report as JSON: exactly what the `costs` operation returns, as one
document on stdout and nothing else. It is for scripts. The text report and `--check` stay as they are.

## Choices (the task left these open)

- **Same data, not a copy.** The command prints `costReport(db)` — the value `operations.ts` returns for `costs` —
  so the two cannot drift. Nothing is added, renamed or left out.
- **Layout:** `JSON.stringify(report, null, 2)` and one newline, through `console.log` and not `say`: `say`
  strips control characters from a line, and a document must not be changed on the way out.
- **No sessions:** the same shape with empty lists. The text form's sentence "No sessions yet." is not printed.
- **`--json` with `--check`:** a `UserError` before the workspace is opened — message `"--json" and "--check" cannot
  be used together: --check proves the report and prints sentences, --json prints the report.`, fix
  `Run them one after the other.` Exit 1, nothing on stdout.
- **Other commands:** `--json` is only read by `cost`. Other commands keep ignoring flags they do not use, as they
  do for `--check` today. Not in scope: `--json` on `runs`, `sessions`, `status`.
- **Help:** the line becomes `cost [--check] [--json]` (keeps the existing `cost-doc` test's pattern).

## Acceptance criteria

1. Given sessions on two lanes (one of unknown cost, one run that did not land), when `softwarefactor cost --json`
   runs, then it exits 0, stderr is empty, stdout is one JSON document ending in one newline, and that document
   equals the `data` the `costs` operation returns through the operator MCP server.
2. Given a workspace with no sessions, when `softwarefactor cost --json` runs, then stdout is the same document the
   operation returns: every list (`usage`, `byTask`, `byLane`, `byAccount`, `byModel`, `failedRuns`) is empty,
   `total.sessions` is 0, the keys are those of a report with a session, and the sentence "No sessions yet." is not
   printed.
3. Given any workspace, when `softwarefactor cost --json --check` (either order) runs, then it exits 1, stdout is
   empty, and stderr names `--json` and `--check` with a `fix:` line.
4. Given the docs, then `docs/costs.md` shows `softwarefactor cost --json`, says it prints what the `costs`
   operation returns and that `--json` with `--check` is refused, and the help line reads `cost [--check] [--json]`.

## Files to touch

- `src/cli.ts`: add `json: { type: "boolean" }` to the options; in the `cost` branch refuse `--json` with
  `--check`, and for `--json` print `JSON.stringify(costReport(db), null, 2)`.
- `src/core/cost.ts`: a small `costJson(db)` next to `costCommand` that returns the text (keeps `cli.ts` thin and
  the printing testable); the operation in `operations.ts` is not changed.
- `src/core/help.ts`: the `cost` line.
- `docs/costs.md`: a section "Reading the report from a script".

## Approach

1. Tests first (done at planning, red): the four files above fail now because `--json` is an unknown option and the
   docs do not mention it.
2. Add the option, the refusal and `costJson`; make tests 1–3 green.
3. Write the docs section and the help line; make test 4 green.
4. Run the existing `cost-*.test.ts` files: the text form is unchanged.

## Risks / out-of-scope

- The document is pretty-printed; a script that reads it with a JSON parser does not care. Compact output was not
  chosen because a person pipes it to a pager as often as to `jq`.
- The report may grow keys later; the doc says the shape is the `costs` operation's, so it grows with it.
- `--json` on other commands, a `--json` for `--check`, and a stable schema file for the report are not done.
