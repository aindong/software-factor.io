# `softwarefactor eval --list`

## Goal

`softwarefactor eval --list` prints each case's id and the one line that says what it shows, in the order the cases
run, and exits 0. It runs no case. With `--break`, `--save` or `--compare` it is refused, exit 1.

## Choices (the task left these open)

- **Source:** the lines come from `CASES` (`id` and `what`), the same list the run walks, so the listing and the run
  cannot differ in order or wording.
- **Layout:** one line per case, `<id padded to the longest id>  <what>`, the layout of a result line without the
  `ok`/`FAIL` mark. No header, no count, no pass rate: nothing was run, so nothing is rated.
- **Refusal:** a `UserError` thrown at the top of `evalCommand`, before the `--compare` file is read, before a gate is
  broken and before any fixture is made. Message: `"--list" only lists the cases: it cannot be used with
  --break, --save or --compare, which need the cases to run.`
  fix: `Run \`softwarefactor eval --list\` alone, or leave --list out.` Exit 1, nothing on stdout, nothing written
  (`--save` makes no file and no folder). The refusal wins over other mistakes in the same command (a missing
  `--compare` file, an unknown `--break` gate).
- **Workspace:** like `eval`, `--list` needs no workspace and touches nothing.
- **Other commands:** they keep ignoring `--list`, as they ignore other flags they do not use.
- **Help:** `eval [--list] [--break <gate>] [--save <file>] [--compare <file>]`.
- **Docs:** `docs/evals.md` gets a short section "Listing the cases" with the command, a sample, and the refusal.
- Not in scope: `--json` for the listing, filtering, or running one case.

## Acceptance criteria

1. Given any directory, when `softwarefactor eval --list` runs, then it exits 0, stderr is empty, and stdout is
   exactly one line per case, in the order the cases run, each `<id>` then spaces then the case's one-line `what`
   (no `ok`/`FAIL` mark, no "cases passed" line). The ids are the eleven the eval runs, in order.
2. Given `--list`, then no case runs: the command returns in well under the time a run takes (a run is several
   seconds per case), and the directory where it ran is unchanged.
3. Given `--list` together with `--break <gate>`, `--save <file>` or `--compare <file>` (either order, any
   combination), when it runs, then it exits 1, stdout is empty, stderr names `--list` and the flag and has a `fix:`
   line, a `--save` target is not created, and a missing `--compare` file is not reported instead.
4. Given the docs and help, then `docs/evals.md` shows `softwarefactor eval --list`, and says that `--list` is
   refused with `--break`, `--save` and `--compare`, and the help line reads `eval [--list] [--break <gate>] ...`.
5. Given the existing eval tests (`eval-passes`, `eval-compare`, `eval-broken-gate`, `eval-doc`), they still pass:
   the run is unchanged.

## Risks / out-of-scope

- The padding uses the longest id, so a new longer id shifts the columns of every line; a script should split on
  the first run of spaces.
- The docs test forbids an em dash and "TODO" in `docs/evals.md`; the new section must not use them.
