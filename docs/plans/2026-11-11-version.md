# `softwarefactor --version` and `softwarefactor version` print the version

## Goal

`softwarefactor --version` and `softwarefactor version` print the `version` of `package.json` on one line and
exit 0. They work outside a git repository, inside a run, and in the built command (`dist/cli.js`). The help
lists the command. No new dependency.

The first try (branch `factor/print-the-version-with-softwarefactor-ve-c5aef240`) was read. Its choices are right
and are kept: the read of `package.json` by URL, the bare version, the early branch in `main()`, the help line, and
its acceptance test (taken over unchanged). Its plan file is replaced by this one, in the form the other plans in
this folder have (its contract lines carried prose after the test path).

## Choices (the task left these open)

- **Where the version comes from.** `package.json`, read at run time with
  `new URL("../package.json", import.meta.url)`. From `src/cli.ts` and from `dist/cli.js` that is the same file,
  the package root, which the published package always holds (`files` lists `dist`, and npm always includes
  `package.json`). Nothing is generated, nothing can drift.
- **Output.** The bare version and a newline (`0.0.0\n`), as `node --version` prints it: no name, no `v`.
- **Where it is handled.** In `src/cli.ts`, right after `parseArgs`, before the help and before the run guard and
  the workspace lookup. So it needs no git, no database, no factory, and works inside a run (it only looks).
- **The flag.** `version: { type: "boolean" }` is added to `parseArgs`. `-v` is not added (not asked).
- **Extra arguments** after `version` are ignored, as for `status` and `inbox`.
- **Help.** One line, `version                  Print the version (also --version)`, which has the command at
  two spaces and mentions `--version`.
- **Not done:** a build stamp, a git sha, the node version, `-v`, a JSON form.

## Acceptance criteria

1. `softwarefactor --version`, run in a folder that is no git repository, prints exactly the `version` of
   `package.json` and a newline on stdout, nothing on stderr, exit 0.
2. `softwarefactor version` does the same.
3. Both also work inside a git repository that has a factory.
4. Both work with `FACTOR_RUN_ID` set (inside a run).
5. `softwarefactor --help` lists `version` as a command (a line starting with two spaces and `version`) and
   mentions `--version`.
6. The built command (`tsc -p tsconfig.build.json` output, `cli.js`) prints the version of the `package.json`
   beside its `dist/` folder, for both spellings, so the version is read and not copied into the source.
7. `package.json` and `pnpm-lock.yaml` gain no dependency; `pnpm typecheck`, `pnpm lint` and `pnpm test` pass.
